# 基础设置实施计划

编写日期：2026-10-06

状态：已实施（2026-10-06）。三个设置子页与真实接口已接入；参数与验收方式见第十节。

## 一、建设目标

基础设置仅保留三个功能入口：

1. 成员与角色。
2. 提醒规则。
3. 使用帮助。

页面沿用现有北大红、浅色背景和学术风格，仅面向桌面浏览器。管理员维护配置，普通成员查看。

## 二、范围约定

本次不包含存放位置管理、分类管理、单位管理、密码管理、数据导出、数据库备份、联系方式管理和独立的权限变更记录页面。

试剂、仪器和样本录入页面的现有位置、分类等字段不因设置范围缩减而取消。

沿用现有计量规则：支持 L 与 mL、kg 与 g 换算，不支持 kg 与 L 换算。本计划不修改换算逻辑。

不新增复杂权限勾选表，仅保留管理员和普通成员两种角色。

## 三、页面结构

基础设置首页展示三个入口，每个入口包含名称、介绍和进入操作：

| 入口 | 介绍 |
| --- | --- |
| 成员与角色 | 查看实验室成员，管理账号状态和操作权限。 |
| 提醒规则 | 设置试剂库存、有效期及仪器校准提醒。 |
| 使用帮助 | 查看台账操作说明与常见问题。 |

点击入口进入对应内容，提供返回基础设置的操作。入口本身允许普通成员进入，权限限制放在具体修改操作上。

成员数量等信息使用真实数据，移除固定演示数字。子页面提供加载、空状态、失败重试，以及保存成功或失败反馈。

## 四、成员与角色

### 4.1 保存和展示的信息

| 信息 | 用途 |
| --- | --- |
| 成员 ID | 系统内部关联成员和历史记录，不要求用户填写。 |
| 姓名 | 列表展示和实际使用人选择。 |
| 登录账号 | 唯一账号，列表展示。 |
| 角色 | 管理员、普通成员。 |
| 账号状态 | 启用、停用。 |
| 创建时间、更新时间 | 展示账号创建和最近维护时间。 |

本模块不展示密码凭据，也不提供修改或重置密码功能；现有登录和个人菜单的密码功能不属于本次改动范围。

### 4.2 功能

- 查看成员列表，支持分页。
- 按姓名或账号搜索。
- 按角色和账号状态筛选。
- 管理员将普通成员设为管理员。
- 管理员将管理员调整为普通成员。
- 管理员停用或恢复成员账号。

成员继续通过现有注册页面创建账号，本次不新增后台创建账号功能，也不新增成员姓名或登录账号编辑功能。

### 4.3 权限和操作规则

- 普通成员可查看、搜索和筛选，尝试管理操作时提示严格为六个字的“您没有该权限”。
- 管理员可调整成员角色和账号状态。
- 设为管理员后，成员获得现有全部管理员权限，包括业务登记、修改及基础设置管理。
- 取消管理员后，仅保留普通成员的查询权限。
- 调整角色或停用账号前，显示确认弹窗，明确目标成员和操作影响。
- 不能降级或停用最后一位有效管理员；已停用管理员不计入有效管理员数量。
- 停用成员保留账号和历史记录，不删除其领用或操作历史。
- 角色或账号状态改变后撤销该成员原有登录会话；启用账号需重新登录，以新权限使用系统。
- 管理员调整自身账号时，同样遵守最后一位有效管理员保护和会话撤销规则。

### 4.4 如何从网页获得管理员账号

**当前网站：网页注册只能创建普通成员，已有管理员可在成员与角色页面授权管理员。** 注册页不提供角色选择；服务端固定按普通成员创建账号，提交管理员角色参数也不能获得管理员权限。

**已实现的网页流程：**

1. 新成员在登录页点击“注册账号”，填写姓名、账号、密码和确认密码。
2. 注册成功后，该账号为普通成员。
3. 已有管理员登录，进入“基础设置 → 成员与角色”。
4. 搜索新成员，点击“设为管理员”。
5. 确认权限变化并保存。
6. 新成员重新登录，获得管理员权限。

不增加可直接公开注册管理员的页面。这里的密码填写属于现有注册流程，不属于设置里的密码管理。

**如果系统还没有管理员：** 当前网页会提示先完成系统初始化，不能通过公开注册创建首位管理员。沿用现有终端初始化方式，在项目目录执行：

```sh
npm run init-admin
```

按提示输入账号、姓名和密码，创建首位管理员后即可使用网页登录。该命令只适用于尚无任何账号的数据库；已有账号时不重复初始化，必要时沿用现有账号管理命令处理。

当前若已有管理员、需要立即新增另一个管理员，可使用现有终端命令 `npm run user -- create`，在角色提示中选择 `admin`。这不是网页注册能力，本次仅记录说明，不执行账号创建。

## 五、提醒规则

### 5.1 保存的信息

| 配置 | 说明 |
| --- | --- |
| 低库存提醒启用状态 | 控制是否在提醒列表中展示低库存提醒。 |
| 试剂临期提醒启用状态 | 控制是否展示临期提醒。 |
| 试剂临期提前天数 | 默认沿用当前 60 天。 |
| 仪器校准提醒启用状态 | 控制是否展示校准日期提醒。 |
| 仪器校准提前天数 | 默认 30 天。 |
| 更新时间 | 最近保存配置的时间。 |

过期状态由有效期自动判断，不提供改变过期判定的配置项。

每种试剂的低库存阈值继续保存在试剂档案中，本模块不新增集中阈值管理功能。

### 5.2 功能和计算规则

- 所有已登录用户可查看当前规则，只有管理员可保存修改。
- 管理员可启用或关闭相应提醒，修改临期及校准提醒提前天数。
- 保存后刷新工作台相关提醒、数量和说明文字；不同页面读取同一份规则。
- 低库存沿用现有口径：可领库存严格低于档案阈值时提醒；阈值为 0 时不提醒。
- 临期按单瓶有效期判断，包含今天和提前天数的边界日；已过期单独展示。
- 有效期未知的试剂瓶不生成临期或过期提醒；报废、耗尽及无余量瓶沿用现有排除规则。
- 仪器校准按下次校准日期判断，覆盖即将到期和已逾期；日期未填写时不生成校准日期提醒。
- 关闭提醒不改变实际库存、有效期、仪器状态或过期瓶的领用限制。
- 现有仪器故障、维护中、待确认等状态展示继续保留。
- 日期计算统一沿用北京时间。
- 提前天数必须为允许范围内的非负整数，上限 365 天，前后端校验一致。

仪器校准日期提醒需要配套实现，不能只保存设置却不生成提醒。

## 六、使用帮助

### 6.1 内容

| 主题 | 内容 |
| --- | --- |
| 账号与权限 | 注册和登录、角色区别、管理员授权流程、“您没有该权限”的含义。 |
| 试剂管理 | 档案与单瓶库存的区别、建立档案、单瓶入库、查询和详情。 |
| 使用登记与历史 | 管理员登记领用、实际使用人与操作者的区别、库存历史和单位换算规则。 |
| 仪器与样本 | 登记、查询、编辑，以及运行状态、校准日期和样本状态的含义。 |
| 提醒与常见问题 | 低库存、临期、过期提醒，日期未填写、登记错误、加载失败和登录失效的处理说明。 |

帮助中的权限说明必须明确普通成员只读，不能沿用“成员登记本人”的旧说明。

登记错误的说明以实际支持能力为准：目前库存历史没有冲销更正入口，不应描述为可直接修改或删除流水。

### 6.2 展示和维护

按主题分组，采用可展开的问答内容，管理员和普通成员均可查看。内容随网站版本维护，首版不提供在线编辑、不新增数据库表、不增加联系方式管理。

帮助文案与最终实现一起验收，不介绍尚未实现的操作。

## 七、后端实施要求

- 复用现有账号体系、登录会话和管理员权限校验。
- 为设置提供成员分页查询接口及角色、状态调整接口；成员查询不得返回密码哈希或会话凭据。
- 不破坏现有领用表单使用的成员查询接口。
- 使用数据库事务保护最后一位有效管理员，避免并发降级或停用绕过限制。
- 在服务端执行权限校验，普通成员直接调用管理接口同样被拒绝。
- 提醒配置保存到数据库，服务重启后保持有效；首次配置沿用现有试剂提醒行为。
- 配置更新和角色调整须防止并发覆盖，遇到冲突提示重新加载。
- 工作台和提醒列表使用同一套配置与计算口径，保留现有分页、错误反馈及刷新机制。
- 使用帮助首版采用静态内容。

## 八、实施顺序

1. 完善三个入口及子页面结构。
2. 实现成员列表、角色调整和账号状态管理。
3. 实现提醒配置存储及工作台联动，包括仪器校准日期提醒。
4. 编写使用帮助，核对页面文案与实际权限一致。
5. 完成相关测试、完整验证和桌面浏览器验收，创建对应 Git commit。

## 九、验收标准

- 基础设置仅包含三个约定入口，均可进入和返回。
- 成员列表来自真实数据，分页、搜索和筛选有效。
- 网页注册固定创建普通成员；只有已有管理员可以将成员设为管理员。
- 角色调整、停用和恢复成功，最后一位有效管理员受到保护，包括并发操作场景。
- 权限变化后原会话失效，新登录使用正确权限，历史记录保持不变。
- 普通成员可查看三个模块，管理按钮和接口均不能绕过权限限制。
- 提醒配置在保存、重新加载及服务重启后保持一致。
- 工作台数量、提醒列表和文字与配置一致；覆盖日期边界、未知日期及关闭提醒场景。
- 使用帮助与实际功能一致，不提供密码管理、导出等范围外入口。
- 在 1280、1440、1920 像素桌面宽度下检查布局，无内容遮挡或异常横向溢出。
- 每次改动编写或更新相关测试，交付前所有测试和验证通过，并创建对应 Git commit。

## 十、实施参数与接口

- 校准提醒默认提前 30 天；临期提醒默认提前 60 天；提前天数范围均为 0–365 的整数。
- GET `/api/v1/settings/members`：真实分页查询，支持 q、role、active、page、page_size。
- PATCH `/api/v1/settings/members/:id`：提交 version 及 role 或 active；事务内保护最后一位有效管理员并撤销变化成员的旧会话。
- GET / PATCH `/api/v1/settings/reminders`：查询及保存共享配置；保存提交五项规则及 version，版本冲突返回 409 并要求重新加载。
- `backend/migrations/006_settings.sql` 保存规则；首次迁移保留既有试剂提醒口径。仪器日期提醒增加校准类型筛选，故障等状态独立保留。
- `/api/v1/users` 仍是现有领用表单的成员选项接口，保持原格式。
- `tests/settings.test.cjs` 覆盖接口、权限、会话、事务、版本、日期边界与持久化；`tests/validate_settings.cjs` 验收三个桌面宽度与设置操作。
